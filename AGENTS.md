# Review guidelines для Codex (claude-gates — репо самого плагина gates)

Ты — независимый ревьюер. Оценивай изменения по инвариантам проекта. Severity
`critical`/`high` = блокирует деплой — ставь только при реальном риске.

**Если ревьюишь ДИЗАЙН/ПЛАН** — суди полноту сценариев (секция BSAC): перечислены ли
топ-уровневые сценарии, закрыт ли каждый fail-open краевой случай, что упущено.

## Blocking (critical/high)

Домен этого репо — сама гейт-система; «деньги» здесь = целостность гейтов у всех
пользователей плагина:

- **Fail-open дыра.** Изменение, при котором гейт молча ПРОПУСКАЕТ то, что обязан
  блокировать: непроверенный деплой, код-коммит без лесенки, обход через конфиг/шим/env.
- **Ослабление через конфиг.** Всё, что позволяет `.codex-gate.yaml` (или его отсутствию/
  битости/незастейдженной правке) снять жёсткие код-пути, деплой-проверки или строгие
  дефолты. Строгий режим при нет/битом конфиге — инвариант.
- **Потеря fail-closed семантики.** Ошибка/outage/дрейф схемы вердикта, трактуемые как
  «чисто»; шим, исполняющий не-тот код или тихо пропускающий при отсутствии плагина.
- **Слом opt-in изоляции.** Плагин начинает вмешиваться в НЕ-онбордженные проекты
  (хуки не exit 0 вне git-репо / без конфига в worktree-OR-HEAD).
- **Молчаливый обход аудита.** Любой skip/обход без записи в audit-лог.
- **Тест, трогающий боевые файлы.** Тест, пишущий в реальные ledger'ы/маркеры/audit
  репо-носителя (изоляция-инварианты conftest).
- **Новый code path без теста, реально входящего в ветку.**
- **Security-класс гейта.** Blocking: внешний/конфигурационный ввод в опасный сток —
  `shell=True` или склейка команд вместо argv (реальная находка 25.07 в `_run_empirical`);
  путь из конфига/ввода без нормализации (обход код-путей, запись вне репо); десериализация
  недоверенного YAML/pickle; секрет или токен в аудите/сообщении блока/вердикте для inframon;
  исполнение кода из worktree вместо каталога плагина (repo-local подмена скрипта).
- **Claude не может быть ЕДИНСТВЕННЫМ blocking-ревьюером** (сужено 07.08.2026, дизайн
  `docs/2026-08-07-host-relative-reviewer-ladder-design.md` §3). Blocking: панель из одного
  ревьюера семейства, которое могло быть автором, и `auto` со скрытой маршрутизацией — гейт
  превращается в самопроверку, сохраняя вид независимого ревью.
  Claude ДОПУСТИМ внутри обязательной пары Codex+Claude: Claude-авторский код всё равно судит
  Codex, а union не даёт снять чужую находку — ослабить исход присутствие однофамильца не может.
  Прежняя безусловная формулировка «ревьюер обязан быть НЕ-Anthropic» требовала третьего
  семейства и тем делала гейт неработоспособным (0.7.0 не пропускал никого).
- **Подменяемость ревьюера — blocking.** Любой путь, которым вызывающий подставляет свой
  бинарь/команду вместо сертифицированного ревьюера (env-override пути к движку, выбор панели
  переменной окружения, repo-local подмена скрипта), равносилен саморевью.

## Medium/low (совещательно)

Нет теста на новую ветку/except; сообщение об ошибке без контекста; пере-блок безобидного
(fail-safe трение); стиль/нейминг.

При сомнении в severity — меньшую, но опиши риск.

## Scope / известные остатки (НЕ флагать как blocking — осознанные решения)

Реестр спеки `docs/2026-07-22-gates-plugin-port-design.md` (Codex-approved, 4 раунда):

- **AGENTS.md вне жёстких код-путей** — наследованный by-design остаток (циклическая
  зависимость дизайн-гейта); ослабление видно в деплой-диффе; pin — Фаза 2.
- **G1 — session-scoped best-effort, cwd-rooted**: произвольный shell (`cp`/`mv`/
  `python -c`), вложенные репо, checkout до-онбординговой ревизии — вне охвата; дизайн-гейт
  fail-open by design (BS3-асимметрия), денежная защита — fail-closed деплой-цепочка.
- **Version-skew при обновлении плагина посреди коммита** — niche; ledger-tree
  валидируется на деплое.
- **Ladder self-attested**; rebase стирает ledger-покрытие (путь — audited LADDER_SKIP);
  кросс-машинные ledger/baseline локальны.

## Реестр остатков Codex-ревью (scope-решения проекта, НЕ пере-флагать)

- **M8 — `declared`-аттестация Codex (07.08.2026, решение владельца продукта, 5 раундов ревью).**
  Codex companion возвращает `model: request.model` (эхо запроса), а `codex_model()` читает
  локальный `~/.codex/config.toml` — фактическая модель НЕ аттестуется. Ревью настаивало, что
  такая запись не может занимать слот независимости в обязательной паре: при скрытой
  маршрутизации на Anthropic-модель оба слота окажутся одного семейства. Возражение логически
  верно и ОТКЛОНЕНО сознательно: альтернатива — deploy-гейт, не работающий ни в одной доступной
  конфигурации (единственный `verified` независимый ревьюер, Gemini, требует стороннего ключа,
  который продукт не делает обязательным). Границы отступления: `declared` допускается только
  для адаптера, запускающего локальный бинарь/плагин под контролем пользователя, только при
  наличии второго `verified`-члена панели, и никогда как единственный член. Снимается
  автоматически, как только companion начнёт отдавать фактическую модель. Дизайн:
  `docs/2026-08-07-host-relative-reviewer-ladder-design.md` §6.

- **Служебная модель того же вендора в `modelUsage` (08.08.2026, уточнение S10).**
  Правило «фактическая модель обязана совпасть с реестром» требовало РОВНО ОДНОЙ модели в
  ответе. Замер 08.08.2026 под обязательным `--safe-mode`: Claude CLI стабильно привлекает
  служебную `claude-haiku-4-5` (вход 5893 / выход ~15) рядом с `claude-opus-5` (выход ~250),
  который и пишет вердикт. Прежнее правило отвергало бы КОРРЕКТНЫЕ ревью. Уточнено: в ответе
  обязана присутствовать сертифицированная модель, она обязана дать НАИБОЛЬШИЙ выход (то есть
  написать вердикт), а любая другая модель — принадлежать тому же семейству. Модель чужого
  вендора и сертифицированная модель, не писавшая ответ, по-прежнему делают артефакт
  невалидным, поэтому исходный смысл S10 (скрытая маршрутизация → блок) сохранён.
  Список служебных моделей НЕ фиксируется по именам: они меняются с версиями CLI, и жёсткий
  список ломался бы при каждом обновлении.

- **R-VERDICT-PROVENANCE — атрибуция модели по токенам не доказывает авторство (08.08.2026 → Фаза 2).**
  `modelUsage` и `result` — независимые поля конверта; связи «этот текст написала эта модель»
  в ответе нет. Гейт требует, чтобы сертифицированная модель присутствовала, имела СТРОГО
  наибольший положительный выход и чтобы все прочие модели были того же семейства (ничьи и
  отсутствующие счётчики теперь отвергаются — раньше `0 == max(0,0)` пропускал артефакт без
  всякой атрибуции). Это эвристика: подмена ВНУТРИ семейства с подходящим распределением
  токенов её пройдёт. Что она гарантирует: чужой вендор отвергается, то есть НЕЗАВИСИМОСТЬ
  панели (не-anthropic ревьюер для anthropic-авторского кода) обеспечивается Codex'ом и от
  этой эвристики не зависит; под риском остаётся КАЧЕСТВО ревью, если CLI подставит более
  слабую модель того же вендора. Настоящее закрытие — per-message provenance (stream-json,
  где терминальное assistant-сообщение несёт имя модели) с fail-closed при отсутствии связи.

- **R-HUMAN-APPROVAL — `resolved-by-user` не доказывает участие человека (08.08.2026 → Фаза 2).**
  Эта адъюдикация мгновенно снимает блокирующую находку и вызывается через тот же CLI, что и
  остальные, то есть доступна агенту, который пишет код. Требование интерактивного терминала
  отсекает дефолтный неинтерактивный вызов, но доказательством не является: агент может
  выделить PTY (проверено ревью 08.08.2026). Механически отличить агента от человека на одной
  машине нельзя — нужен внеполосный подписанный одноразовый артефакт, привязанный к репозиторию,
  baseline, id находки и решению. До этого защита держится на ГРОМКОСТИ: каждое такое решение
  пишется в аудит меткой `HUMAN-APPROVAL` с session id и причиной, чтобы подделанное одобрение
  было заметно постфактум. Практическое следствие: эскалация к человеку — организационный
  контроль, а не технический.

- **R-ARTIFACT-PROVENANCE — подмена БИНАРЯ ревьюера в собственном HOME (07.08.2026 → Фаза 2).**
  Гейт исполняется от имени того же пользователя, чей домашний каталог содержит и `claude`
  (`~/.local/bin`, `~/.claude/local`, `~/.volta`, `~/.nvm`), и companion-плагин. Эти артефакты
  caller-writable по определению, поэтому вызывающий может подменить любой из них шимом,
  печатающим `Verdict: approve` с ожидаемым `modelUsage` — проверка фактической модели тогда
  выполняется НАД ДАННЫМИ ШИМА. Закрыто всё, что закрывается кодом гейта: переменные окружения
  (аллоулист из 8 значений), путь к движку (доверенный HOME из БД пользователей, абсолютный
  `node`, запрет repo-local), маршрут через конфиг (стерильный gate-owned `CODEX_HOME` только
  с моделью). НЕ закрывается и не может быть закрыто патчем гейта: доверие к самим артефактам —
  нужны immutable/system-owned установки либо проверка подписи/дайджеста до запуска, что ломает
  обычное обновление CLI. Это та же семья, что R-CERT-PROVENANCE: без доверенной инфраструктуры
  исполнения «операторская учётка враждебна» не моделируется. Практическая граница: гейт
  защищает от СЛУЧАЙНОГО обхода и заставляет любое изменение gated-кода пройти ревью, но НЕ
  является техническим барьером против того, кто владеет машиной, — включая агента,
  исполняющегося с её правами (см. R-HUMAN-APPROVAL: снять находку через `resolved-by-user`
  агент технически может). Ценность гейта здесь — принуждение к процессу и следы в аудите,
  а не невозможность обхода.

- **R-CERT-PROVENANCE — подделка отчёта сертификации вместе с реестром (07.08.2026 → Фаза 2).**
  Связка отчёта с реестром (path, sha256, corpus digest, provider/adapter/model/role/
  certification_id, полная матрица кейс×повтор, единственная фактическая модель во всех строках,
  путь внутри поставляемого каталога) доказывает согласованность двух коммитабельных артефактов,
  но не доверенное исполнение: автор может написать отчёт с `pass: true`, посчитать sha и
  поправить реестр одним коммитом. Полное закрытие требует подписи CI над отчётом, digest'ом
  корпуса, digest'ом кода адаптера и идентичностью реестра с проверкой подписанта — отдельная
  инфраструктура, Фаза 2. До неё защита: реестр сертификаций — код-путь в `.codex-gate.yaml`,
  то есть его правка сама проходит deploy-гейт и независимого ревьюера. Дизайн: §7.

- **Редакция секретов — defense-in-depth по ОБРАЗЦАМ, не гарантия (25.07, 7 раундов ревью).**
  `redact_secrets` закрывает распознаваемые формы: помеченные пары `KEY=value` (в т.ч. ключ как
  часть идентификатора вроде `AWS_SECRET_ACCESS_KEY`), схемы аутентификации (Bearer/Basic/Digest
  + поля `response/nonce/cnonce/opaque`), префиксы провайдеров (sk-/ghp_/github_pat_/xox*/AKIA/
  ASIA), JWT, подписи в URL, DSN-креды (в т.ч. без имени пользователя), длинный неразрывный
  токен ≥40. Применяется у ВСЕХ 8 источников недоверенного текста (реестр в коде
  `codex_review_gate.py` рядом с `redact_secrets`).
  **НЕ ловится по построению (осознанный остаток, НЕ флагать как blocking):** значение без
  распознаваемой формы и без метки (произвольная проза, короткие/низкоэнтропийные значения ниже
  порогов), а также секрет, который оператор проносит намеренно. Хэши/SHA и пути конфигов НЕ
  редактируются намеренно (64-hex попал бы под правило длинного токена и сломал бы маркер).
  Новый ИСТОЧНИК недоверенного текста → редактировать в его источнике и дописать в реестр;
  новая ФОРМА секрета → правило добавлять, только если это широко стандартный формат.

- **empirical ML-E5 (2026-07-22, residual-failsafe → Фаза 2):** env-ослабление неизменной
  тест-команды (`PATH=/tmp/shims make deploy` подменяет `pytest` шимом; `PYTEST_ADDOPTS` и т.п.).
  НЕ чиним: тест-раннеру environment нужен (санитизация = fail-safe пере-блок), а оператор,
  задающий env на деплой, эквивалентен задающему `EMPIRICAL_SKIP` — защита от злонамеренного
  оператора вне охвата Фазы 1. Герметичный прогон в изолированном образе из отревьюенного
  коммита — Фаза 2 (тот же immutable-artifact-биндинг, что закрывает reviewed≡deployed). Порог
  эмпирического гейта: «поймать сломанные тесты + сделать конфиг-обходы аудируемыми», НЕ
  «остановить оператора с доступом к деплой-машине». Спека: docs/2026-07-22-empirical-gate-design.md ML-E5.
