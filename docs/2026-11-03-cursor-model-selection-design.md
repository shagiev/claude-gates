# Актуальная модель Cursor reviewer — дизайн

Дата: 2026-11-03. Tier: 2 — выбор ревьюера влияет на независимость deploy-гейта.

## Задача

Убрать устаревание захардкоженной `cursor-grok-4.5-high` в LEGACY `resolve_cursor_model`, не включая
`auto` и не ослабляя независимость ревьюера. По умолчанию выбирать самую новую доступную Grok
`high` модель по фактическому `cursor-agent models`.

## Решения и альтернативы

- **Просто обновить константу до 4.7.** Отвергнуто: повторится та же проблема при следующем релизе.
- **Включить `auto`.** Отвергнуто: скрытая маршрутизация, нет аттестации фактической модели.
- **Любая не-Anthropic модель вместо Grok.** Отвергнуто: OpenAI+OpenAI панель теряет семейную
  независимость. Нужна именно Grok/xAI `high`, без fallback на GPT.
- **Сначала мигрировать внешний проект на portable, затем удалить legacy.** Отвергнуто для этой
  задачи. Потребитель — отдельный проект вне этого репозитория, где `cursor-agent` уже используется
  как fallback; атомарно изменить его конфигурацию и поставку плагина здесь нельзя, а compatibility
  shim сохранил бы тот же legacy trust path. Главное: portable certified plan намеренно закрепляет
  конкретные slug до corpus certification и reviewed promotion, поэтому после миграции новая модель
  всё равно не выбирается автоматически — требование «всегда актуальная» не выполняется. Portable
  остаётся строгим deploy-путём; динамический выбор ограничен существующим legacy-совместимостью.
- **Просто удалить legacy resolver/adapter.** Отвергнуто: это ломает fallback внешнего проекта без
  миграции, а миграция сама по себе проблему актуальности не решает (предыдущая альтернатива).
- **Curated static allowlist вместо discovery.** Отвергнуто: он снова устаревает и требует релиза
  плагина на каждую модель. Certification нужна для portable blocking-допуска, но не является
  источником актуальности; в legacy доступность Grok `high` проверяется у фактического CLI.
- **Динамический выбор по `cursor-agent models`. Выбрано.** Discovery подтверждает ТОЛЬКО доступность
  slug, не сертификацию. Из доступных выбирается Grok с максимальной числовой версией, только exact
  `-high` (не `high-fast`, не `low`, не prerelease). `CURSOR_REVIEW_MODEL` — явный override с теми же
  ограничениями и обязательным присутствием в списке.
- **При недоступном списке использовать старую константу.** Отвергнуто: возврат к устаревшей модели
  молча. Нет списка/подходящей Grok — fail-closed.
- **Привязать запуск к SHA-256 бинаря проверками до/после или временным снимком.** Отвергнуто:
  pathname-проверки не закрывают TOCTOU, а реальный `cursor-agent` — shell-обёртка, исполняющая
  соседние `node` и `index.js`, поэтому снимок одного файла меняет семантику запуска. Полный снимок
  установки по-прежнему перезаписываем тем же пользователем. Это существующий принятый остаток
  `R-ARTIFACT-PROVENANCE`; задача выбора модели его не расширяет и не объявляет решённым.

## Portable path

Portable deploy-путь НЕ меняется: он продолжает брать модель только из gate-owned certified records
с artifact-bound corpus report. Discovery НЕ назначает blocking-ревьюера и НЕ заменяет сертификацию.
Новая модель вводится отдельным candidate → corpus certification → reviewed promotion.

## Discovery и существующая граница исполнения

- Binary резолвится один раз через существующий legacy `_resolve_cursor_bin`; тот же путь передаётся
  discovery и последующему review-launch, второго PATH-резолва нет. Прямой вызов resolver'а без
  переданного binary сохраняет текущий интерфейс и сам использует `_resolve_cursor_bin`.
- Discovery вызывается с `_certified_subprocess_env(cursor_auth=True)`, отдельным стерильным cwd,
  коротким таймаутом и лимитом 256 КБ на stdout и stderr. Opt-in передаёт только `CURSOR_API_KEY`
  для key-only аутентификации; `CURSOR_API_ENDPOINT` и прочие routing-переменные не наследуются,
  другие адаптеры ключ не получают. Потоки пишутся во временные файлы в sterile cwd; размер
  проверяется до чтения, поэтому превышение не материализуется в памяти целиком. Превышение,
  rc != 0, timeout и битый вывод — fail-closed. Это ограничивает новый вызов `models`; существующий
  review-launch, его env/cwd и обработка ответа НЕ меняются. Тесты подменяют subprocess, а не ходят
  наружу.
- **Общий certified runner и изолированный Cursor profile.** Не входят в этот патч. Они меняют
  существующую trust boundary и требуют отдельного дизайна аутентификации: ephemeral HOME без
  переноса credentials делает CLI недоступным, а копирование credentials — отдельный секретный
  контур. Cursor user hooks/rules/plugins/MCP и caller-controlled routing — уже существующий риск
  обоих текущих адаптеров, а не последствие выбора slug; этот дизайн не объявляет его решённым.
  Подмена caller-writable CLI остаётся в `R-ARTIFACT-PROVENANCE`. Отдельный дизайн обязан рассмотреть
  отключение user/team customization и доказуемую изоляцию до того, как называть runner trusted.

## Грамматика и порядок версий

Кандидат: `^(?:cursor-)?grok-([0-9]{1,9})\\.([0-9]{1,9})(?:\\.([0-9]{1,9}))?-high$`.
Версия — числовой tuple `(major, minor, patch=0)`, не лексикографическая. Не-ASCII цифры и
компоненты длиннее девяти цифр не являются кандидатами. `cursor-` префикс необязателен.
При равной версии два slug — выбирается канонический `cursor-grok-*`, если он есть; иначе обычный
`grok-*`. Суффиксы `(current)`, `(default)` и их комбинация через запятую без описания удаляются
перед разбором. Дубли с разными
версиями сравниваются по tuple, не по строке. `high-fast`, `low`, `auto`, prerelease,
нестандартные строки и Anthropic отклоняются.

## Сценарии и приёмочные критерии (BSAC)

- **S1. Новая версия.** 4.5, 4.6, 4.7 в любом порядке → 4.7.
- **S2. Префикс и версии.** `grok-4.10-high` новее `cursor-grok-4.9-high`; `cursor-` необязателен.
- **S3. Дубли и варианты.** Две формы одной версии → канонический `cursor-grok-*`; `high-fast` и
  `low` не кандидаты; prerelease/malformed — ошибка, не выбор.
- **S4. Override.** Разрешённый Grok `high` из списка используется даже при наличии более новой;
  GPT override, `auto`, Claude, неизвестный ID и ID вне списка — ошибка.
- **S5. Ошибка списка.** CLI не найден, rc != 0, timeout, пустой список, нет Grok, нет валидных
  кандидатов, обрезанный вывод → `(None, причина)`, ревью не запускается.
- **S6. Семейства.** Anthropic и `auto` отклоняются всегда; GPT fallback отсутствует.
- **S7. Вызов.** Адаптер использует выбранную модель в `--model` и audit; discovery и ревью получают
  один заранее resolved binary. Discovery имеет ограниченные таймаут/вывод и стерильные env/cwd;
  существующий запуск ревью не меняется. Сетевых вызовов из тестов нет.

## EARS

- **EARS-1.** WHEN список содержит несколько Grok `high` версий, THE resolver SHALL выбрать
  максимальную числовую версию независимо от порядка строк и префикса `cursor-`.
- **EARS-2.** IF модель не является разрешённой Grok `high` из фактического списка, THEN resolver
  SHALL отклонить её.
- **EARS-3.** IF список нельзя получить или в нём нет разрешённой Grok `high`, THEN resolver SHALL
  вернуть ошибку и не запускать ревью.

## Намеренно вне охвата

- Оценка качества кроме версии и суффикса `high`: не придумываем метрику.
- Кэширование списка между процессами: оно увеличивает окно устаревания; запрос идёт при каждом
  резолве.
- Изменение portable certification registry: новые модели проходят отдельную сертификацию.
