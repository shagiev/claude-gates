# Актуальная модель Cursor reviewer — дизайн

Дата: 2026-11-03. Tier: 2 — выбор ревьюера влияет на независимость deploy-гейта.

## Задача

Убрать устаревание захардкоженной `cursor-grok-4.5-high` в LEGACY `resolve_cursor_model`, не включая
`auto` и не ослабляя независимость ревьюера. По умолчанию выбирать самую новую доступную Grok
`high` модель по фактическому `cursor-agent models`.

## Решения и альтернативы

- **Просто обновить константу до 4.7.** Отвергнуто: повторится та же проблема при следующем релизе.
- **Включить `auto`.** Отвергнуто: скрытая маршрутизация, нет аттестации фактической модели.
- **Любая не-Anthropic модель вместо Grok.** Отвергнуто: OpenAI+OpenAI панель теряет семейную
  независимость. Нужна именно Grok/xAI `high`, без fallback на GPT.
- **Динамический выбор по `cursor-agent models`. Выбрано.** Discovery подтверждает ТОЛЬКО доступность
  slug, не сертификацию. Из доступных выбирается Grok с максимальной числовой версией, только exact
  `-high` (не `high-fast`, не `low`, не prerelease). `CURSOR_REVIEW_MODEL` — явный override с теми же
  ограничениями и обязательным присутствием в списке.
- **При недоступном списке использовать старую константу.** Отвергнуто: возврат к устаревшей модели
  молча. Нет списка/подходящей Grok — fail-closed.

## Portable path

Portable deploy-путь НЕ меняется: он продолжает брать модель только из gate-owned certified records
с artifact-bound corpus report. Discovery НЕ назначает blocking-ревьюера и НЕ заменяет сертификацию.
Новая модель вводится отдельным candidate → corpus certification → reviewed promotion.

## Доверенный канал discovery

Абсолютный binary резолвится один раз через `_resolve_cursor_bin` и используется и для discovery, и
для запуска. Discovery вызывается с `_certified_subprocess_env()` и стерильным cwd, коротким
таймаутом и лимитом вывода 256 КБ. PATH/HOME/CURSOR_API_ENDPOINT/proxy/repo-local/symlink binary,
смена binary между discovery и запуском, обрезанный/битый вывод — fail-closed. Тесты подменяют
subprocess, а не ходят наружу.

## Грамматика и порядок версий

Кандидат: `^(?:cursor-)?grok-(\\d+)\\.(\\d+)(?:\\.(\\d+))?-high$`. Версия — числовой tuple
`(major, minor, patch=0)`, не лексикографическая. `cursor-` префикс необязателен. При равной версии
два slug — выбирается канонический `cursor-grok-*`, если он есть; иначе обычный `grok-*`. Дубли с
разными версиями сравниваются по tuple, не по строке. `high-fast`, `low`, `auto`, prerelease,
нестандартные строки и Anthropic отклоняются.

## Сценарии и приёмочные критерии (BSAC)

- **S1. Новая версия.** 4.5, 4.6, 4.7 в любом порядке → 4.7.
- **S2. Префикс и версии.** `grok-4.10-high` новее `cursor-grok-4.9-high`; `cursor-` необязателен.
- **S3. Дубли и варианты.** Две формы одной версии → канонический `cursor-grok-*`; `high-fast` и
  `low` не кандидаты; prerelease/malformed — ошибка, не выбор.
- **S4. Override.** Разрешённый Grok `high` из списка используется даже при наличии более новой;
  GPT override, `auto`, Claude, неизвестный ID и ID вне списка — ошибка.
- **S5. Ошибка списка.** CLI не найден, rc != 0, timeout, пустой список, нет Grok, нет валидных
  кандидатов, обрезанный вывод → `(None, причина)`, ревью не запускается.
- **S6. Семейства.** Anthropic и `auto` отклоняются всегда; GPT fallback отсутствует.
- **S7. Доверенный вызов.** Адаптер использует выбранную модель в `--model` и audit; список берётся
  с ограниченным таймаутом, стерильным env/cwd и без сетевых вызовов из тестов.

## EARS

- **EARS-1.** WHEN список содержит несколько Grok `high` версий, THE resolver SHALL выбрать
  максимальную числовую версию независимо от порядка строк и префикса `cursor-`.
- **EARS-2.** IF модель не является разрешённой Grok `high` из фактического списка, THEN resolver
  SHALL отклонить её.
- **EARS-3.** IF список нельзя получить или в нём нет разрешённой Grok `high`, THEN resolver SHALL
  вернуть ошибку и не запускать ревью.

## Намеренно вне охвата

- Оценка качества кроме версии и суффикса `high`: не придумываем метрику.
- Кэширование списка между процессами: оно увеличивает окно устаревания; запрос идёт при каждом
  резолве.
- Изменение portable certification registry: новые модели проходят отдельную сертификацию.
