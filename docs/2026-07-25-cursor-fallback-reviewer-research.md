# Cursor как резервный ревьюер при исчерпании Codex-квоты — эмпирика

**Дата замеров:** 2026-07-25 (цифры устаревают — способ воспроизведения ниже).
**Мотив:** квота Codex исчерпалась (сброс ~28.07.2026 20:06) → нужен переключаемый второй
независимый ревьюер. Вопрос: какую модель в установленном `cursor-agent` использовать,
с учётом КАЧЕСТВА и ЗАТРАТ.

## Способ воспроизведения

```bash
cursor-agent --list-models                    # доступные модели аккаунта
cursor-agent -p --output-format json --mode ask --trust --model <M> "<промпт>"
# usage лежит в .usage {inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens}
```
Тест-промпт: наш текст-контракт (`Verdict: …` + `- [severity] title (file:line)`) + дифф-ловушка
с двумя дефектами: (а) очевидный — `divide()` стал возвращать `None`, а вызывающие делают
`divide(x,y) * 2` → TypeError; (б) тонкий — ранний `return` до `conn.close()` → утечка соединения.
Вывод парсился НАШИМ парсером (`parse_review_output`) — проверялся не только смысл, но и
соблюдение контракта.

## Результаты: качество (все 4 кандидата)

| Модель | Время | Наш парсер | Нашла (а) | Нашла (б) |
|---|---|---|---|---|
| `cursor-grok-4.5-low` | 17–20 с | valid, 3 находки, blocking | ✅ high | ✅ high |
| `cursor-grok-4.5-high-fast` | 13–19 с | valid, 3 находки, blocking | ✅ high | ✅ medium |
| `gpt-5.3-codex-high-fast` | 13–14 с | valid, 3 находки, blocking | ✅ high | ✅ medium |
| `gpt-5.6-sol-high-fast` | 11 с | valid, 2 находки, blocking | ✅ high | ✅ medium |

**Вывод по качеству:** на этом диффе различий нет — все нашли оба дефекта, включая тонкий,
и все соблюли текст-контракт с первого раза (парсер `valid=True`, `blocking=True`). Дифф был
простым: качественную дифференциацию он не даёт, выбор решают затраты и совместимость.

## Результаты: затраты (замерено, не из документации)

Тарифы (июль 2026): Grok 4.5 — **$2/M вход, $6/M выход**; fast-вариант — **$4/M и $18/M**;
для сравнения Claude Opus 4.8 — $5/$25.

| Модель | in / out токенов | $/ревью | $/100 ревью |
|---|---|---|---|
| `cursor-grok-4.5-low` | 21455 / 676 | **$0.045** | $4.50 |
| `cursor-grok-4.5-high-fast` | 21460 / 784 | $0.100 | $10.00 |

**Главный факт о затратах: ~20k входных токенов — фиксированный оверхед `cursor-agent`, а не
контекст репозитория.** Проверено: из корня репо `in=21455`, из ПУСТОГО каталога `in=20377`
(разница ~5%). Наш промпт — ~300 токенов, т.е. **стоимость вызова почти полностью определяется
системным оверхедом CLI и оптимизации не имеет**: «пол» ≈ $0.04 за ревью на тарифе $2/M.
Следствия:
- `-fast`-варианты платят 2.2× за ~4 секунды — для деплой-гейта бессмысленно.
- Разница «low/high» по цене токена нулевая ($2/$6 у обоих), отличается только объём
  reasoning-выхода → на сложных диффах `high` дороже незначительно (выход ≪ входа).
- Порядок величины: 10 ревью/день ≈ $0.45/день ≈ **$14/мес** в худшем случае (если Codex
  недоступен весь месяц). Codex через подписку ChatGPT остаётся $0 маржинально → он первичен,
  Cursor — резерв.

## Рекомендация

**`cursor-grok-4.5-high`** (НЕ `-fast`) как резервный ревьюер; `cursor-grok-4.5-low` — если
нужен минимум затрат (на тесте не проиграл в качестве).

Обоснование: качество на уровне остальных, тариф вдвое-втрое ниже fast-вариантов, семейство
отличается и от Claude (строит код), и от Codex (первичный ревьюер) → добавляет РАЗНООБРАЗИЕ
взгляда, что по нашему же ресёрчу (arxiv 2604.19049) и есть источник ценности кросс-модельного
ревью.

**Альтернатива с другим смыслом:** `gpt-5.3-codex-high-fast` — то же семейство, что первичный
ревьюер, но биллинг через Cursor (работает, когда исчерпана квота ChatGPT). Он не добавляет
разнообразия, зато сохраняет КАЛИБРОВКУ severity внутри уже идущей серии сходимости
(finding-ledger с `[DUP:]`-переговорами между раундами) — смена судьи посреди серии иначе
ломает преемственность адъюдикаций. Кандидат на роль «дожать текущую серию», тогда как Grok —
«новый независимый взгляд для новой серии».

## ЖЁСТКОЕ ограничение (не конфиг, а код адаптера)

В списке моделей Cursor присутствуют `claude-opus-5-thinking-high`, `claude-opus-4-8-*`,
`claude-fable-5-*` и `auto`. **Ни одна Anthropic-модель и НИКОГДА `auto` не могут быть
ревьюером**: Claude пишет код в этом контуре, и Claude-ревьюер молча превращает независимый
гейт в самопроверку — ровно тот провал, против которого гейт существует (80+ агентов одного
семейства единогласно подтверждали несуществующий баг). `auto` опасен тем, что маршрутизация
скрытая и может увести на Claude-модель. Значит: модель пиньуется в коде адаптера с
allow-list не-Anthropic значений, `auto` в чёрном списке.

## Грабли эксплуатации (проверено на живом CLI)

1. **`--trust` обязателен.** Без него cursor-agent печатает «⚠ Workspace Trust Required»,
   отдаёт `rc=1` и ПУСТОЙ stdout — для нашего гейта это выглядит как outage. Хуже: первый
   вызов без `--trust` **завис интерактивно** и был убит по таймауту 5 мин. Вывод: адаптер
   ОБЯЗАН передавать `--trust` И иметь свой таймаут (headless-контур не должен уметь висеть).
2. **`--mode ask`** — read-only режим; ревьюер не должен иметь права правки (bounded authority).
3. **Авторизация протухает молча:** `cursor-agent status` рапортовал «Logged in (unable to
   fetch user details)», а реальные вызовы возвращали «Authentication required» → нужен
   `cursor-agent login`. Класс «не запустилось ≠ прошло»: у нас это уже fail-closed, но
   сообщение должно нести причину (как `outage_details` для Codex).
4. **`--list-models` до логина** отвечает «No models available for this account» — не путать
   с отсутствием моделей.
5. `--output-format json` даёт `usage` → расход можно писать в аудит/вердикт (наблюдаемость
   затрат вместо догадок).

## Отвергнутые варианты

- **Тихий авто-фоллбек Codex→Cursor при quota-ошибке.** Отвергнут: смена судьи посреди серии
  сходимости без следа; оператор не знает, кто выдал вердикт. Правильно — ЯВНОЕ переключение
  (`REVIEW_PROVIDER=cursor`) + аудит + провайдер в finding-ledger и в вердикте для inframon.
- **`-fast`-варианты.** 2.2× цена за ~4 с — для гейта, который и так ждёт минуты, не нужно.
- **`auto`.** Скрытая маршрутизация → риск Claude-модели (см. ограничение выше).
