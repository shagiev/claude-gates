# Дизайн: пакетный `compute_tree` + атрибуция телеметрии по машине (0.9.4)

Первые данные телеметрии с двух машин показали, где уходит время и почему это надо чинить
именно на маке.

## 1. Задача

### Что показали замеры

Один репозиторий (`wb-ad-ruler`, ~578 файлов), одна фаза, две машины:

| | `compute_tree` | файлов |
|---|---|---|
| мак | **12 275 мс** | 579 |
| дев-сервер | **2 627 мс** (медиана) | 578 |

**Мак в 4,7 раза медленнее.** Дело не в алгоритме, а в числе подпроцессов: `2N+3` вызовов git
на дерево, и стоимость запуска процесса на macOS кратно выше. Меряй я только на сервере —
недооценил бы выигрыш вчетверо.

Лесенка зовёт `compute_tree` **6 раз за цикл** (`begin`+`mark` × три прохода) плюс по разу на
каждой заблокированной попытке коммита. На маке это **~75 секунд чистого хэширования на
коммит**. Это и есть предметный ответ на «гейты сильно увеличивают время задач».

### Вторая задача: сводка врёт без атрибуции

Сейчас в событии нет машины. Сложить 12-секундный и 2,6-секундный `compute_tree` в одну
медиану — получить число, которого нет ни на одной машине. Проверено руками: пришлось держать
шарды в разных каталогах, чтобы сводка не соврала.

## 2. Подход

### Р1. Пакетное хэширование: `2N+3` подпроцессов → константа

Механика проверена ранее на git 2.50.1:

- `git hash-object --no-filters -w --stdin-paths` — весь список обычных файлов ОДНИМ вызовом,
  порядок вывода = порядок ввода;
- `git update-index -z --index-info` — ВСЕ записи одним вызовом, формат
  `mode SP oid TAB path NUL`, включая режимы `120000` и `160000`.

Итог: `~4 + K_симлинков + S_подмодулей` подпроцессов вместо `2N+3`. Симлинки и подмодули
остаются поштучными — их единицы, а батчить их нечем (`--stdin` принимает одно содержимое).

**Что обязано остаться неизменным:** пере-хэш С ДИСКА, то есть иммунитет к clean-фильтрам,
racy-index и `assume-unchanged`. Пакетность этого не размывает: `--stdin-paths` читает те же
файлы тем же `--no-filters`.

**Три ловушки, каждая уже стоила инцидента в этом файле:**

1. **У `--stdin-paths` НЕТ `-z`** — разделитель только LF. Путь с `\n` ломает пакет (проверено:
   `rc=128`, падает громко, не молча). Такие пути идут ПОШТУЧНО через `--stdin` с байтами
   файла. Аллоулист формы, а не денилист: в пакет попадает только путь без `\n`.
2. **Проверка длины обязательна.** При обрыве git отдаёт ЧАСТИЧНЫЙ вывод. Без сверки
   `len(oids) == len(paths)` записи разъедутся по путям — то есть тихо неверный tree-хэш,
   ровно тот класс, который чинили в 0.9.1. Несовпадение → `TrustedGitError`.
3. **Кодировка.** Пути декодированы `surrogateescape`; в stdin уходят через `os.fsencode`,
   иначе не-UTF-8 имя уронит `.encode()` мимо диагностики.

### Р2. `host` в событии — хэш, а не имя

Новое скалярное поле: `hashlib.sha256(uname().nodename)[:16]`. Хэш по той же причине, что и
`session`: сшивать нужно по РАВЕНСТВУ, а имя машины — это идентифицирующая строка из
окружения, и попадать в файл, который приложат к отчёту, она не должна. Сводка группирует по
`host` и НЕ смешивает машины в одной строке.

### Что НЕ делается

- **Не трогается модель дерева.** Меняется только КАК считаются хэши, не ЧТО попадает в дерево.
  Все инварианты 0.9.1–0.9.2 (skip-worktree, gitlink, unmerged, невидимое содержимое против
  HEAD) остаются как есть.
- **Не строится сборщик телеметрии в гейте.** Проверено на живом: `ssh`+`rsync` по имеющемуся
  ключу решают задачу без единой строки в гейте. Сетевой код в обязательном гейте — новый режим
  отказа; парк машин — территория `inframon` (записанное решение о границе).

## 3. Файлы

- `plugins/gates/scripts/ladder_gate.py` — `compute_tree`: классификация → пакетный хэш →
  один `update-index --index-info`.
- `plugins/gates/scripts/codex_review_gate.py` — поле `host`, валидатор, группировка в сводке.
- `tests/test_ladder_gate.py`, `tests/test_telemetry.py`.
- Версия 0.9.4, `CHANGELOG.md`.

## 4. Инварианты

- `compute_tree` == `git add -A && git write-tree` — **оракул уже есть** и проверяется на
  ГРЯЗНЫХ деревьях; пакетная версия обязана пройти его без единой правки теста.
- Пере-хэш с диска сохраняется; clean-фильтры по-прежнему обходятся (`--no-filters`).
- Частичный вывод git — отказ, а не тихо неверный хэш.
- Каждый новый code path — тест, реально входящий в эту ветку.

## 5. BSAC

| # | Сценарий | Как проверяется |
|---|---|---|
| S1 | **Тот же tree-хэш**, что у старой реализации, на всех накопленных формах: симлинк на файл/директорию/битый, не-UTF-8 цель, подмодуль (инициализированный, деинициализированный, удалённый), sparse checkout, unmerged, вложенный untracked-репозиторий, `assume-unchanged` | все существующие тесты `test_ladder_gate.py` зелёные БЕЗ правок — это и есть главный критерий |
| S2 | Равенство `git add -A` на ГРЯЗНОМ дереве | существующие `test_compute_tree_equals_git_add_all_on_dirty_*` |
| S3 | **Путь с `\n`** хэшируется верно (не попадает в пакет) | новый тест: файл с переводом строки в имени → дерево == `git add -A` |
| S4 | **Частичный вывод** `--stdin-paths` → `TrustedGitError`, а не разъехавшиеся записи | тест с подменённым `_git_mutate`, отдающим меньше oid, чем путей |
| S5 | Не-UTF-8 **имя файла** не роняет пакет | тест на Linux-подобной ФС; на APFS не воспроизводится — заявлено честно |
| S6 | **Ускорение измеримо**: подпроцессов на дерево из N файлов — константа, а не `2N+3` | тест считает вызовы `_git_mutate` на репо из 50 файлов: было ≥103, стало ≤10 |
| S7 | `host` в событии, сводка **группирует по машинам** и не смешивает | тест на двух наборах шардов с разными `host` |
| S8 | В событии по-прежнему нет строк из окружения (имя машины — хэш) | существующий позитивный тест на алфавит + `uname` не встречается в файле |

### Денежные / актуаторные краевые случаи

| # | Риск | Как предотвращается |
|---|---|---|
| M1 | Пакетный хэш даёт ДРУГОЙ tree-хэш → все маркеры лесенки инвалидируются молча | S1/S2: оракул `git add -A` и весь накопленный набор форм. Если хэш поедет — тесты красные |
| M2 | Разъезд «oid ↔ путь» при частичном выводе → тихо неверный хэш на chokepoint'е целостности | Сверка длин, отказ. S4 |
| M3 | Путь с `\n`/не-UTF-8 молча выпадает из дерева | В пакет попадает только путь без `\n` (аллоулист), остальные — поштучно. S3 |
| M4 | Оптимизация размывает иммунитет к clean-фильтрам, и в дерево попадёт ПРЕОБРАЗОВАННОЕ содержимое | `--no-filters` сохранён в пакетном вызове; существующий тест на clean-фильтр остаётся зелёным |
| M5 | Имя машины утекает в файл, который приложат к отчёту | `host` — хэш. S8 |
