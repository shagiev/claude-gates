# Переключение ревьюера + сессионное выключение — дизайн

**Дата:** 2026-07-25. **Статус:** design (на ревью). **Tier:** 2 (управляет наличием
независимого ревьюера — guard'а деплой-актуатора; провал в fail-open = непроверенный деплой).
**Опирается на:** эмпирику `docs/2026-07-25-cursor-fallback-reviewer-research.md` (выбор модели,
затраты, грабли CLI).

## Задача

1. **Явно переключать ревьюера** (codex ↔ cursor) — нужно, когда квота одного исчерпана
   (реальный случай 25.07: Codex до 28.07) или нужен другой независимый взгляд.
2. **Выключать ревьюера в рамках сессии** — чтобы в сессии, где ревьюер недоступен, он не
   требовал ревью и не жёг вызовы впустую.
3. **Включать ОБОИХ ревьюеров для сложных случаев** — максимальная гарантия там, где цена
   ошибки высока (актуатор/необратимое/деньги).

## Ф1. Явное переключение провайдера

`REVIEW_PROVIDER=codex|cursor|both` (env, per-invocation; дефолт `codex`). Конфиг-ключа НЕТ
осознанно: провайдер — операционное решение момента («у этого кончилась квота»), а не свойство
репозитория; в конфиге он стал бы ещё одной поверхностью ослабления с pin-механикой (как
`deploy`-секция), не давая ничего.

- Неизвестное значение (`cursorr`, пусто-но-задано) → **БЛОК** (fail-closed): тихий фоллбэк на
  codex скрыл бы опечатку и создал ложное впечатление «ревьюил тот, кого просили».
- Провайдер пишется в аудит, в **раунд finding-ledger** (кто судил этот раунд — иначе
  `[DUP:Fx]`-переговоры между раундами теряют смысл при смене судьи) и в **вердикт для
  inframon** (поле `providers: [...]` — всегда список, даже для одного; схема → 2).

**Кэш чистого ревью ПРИВЯЗАН к ИДЕНТИЧНОСТЯМ ревьюеров (R1-F1 + R2-F1, оба найдены ревью —
реальный fail-open).** `write_ledger` пишет канонический набор
`reviewers: [{"provider": "codex", "model": "gpt-5.6-sol"}, {"provider": "cursor", "model": "cursor-grok-4.5-high"}]`
(модель — фактически использованная), а `read_valid_ledger` считает запись годной ТОЛЬКО если:
- набор `reviewers` **точно** совпадает с запрошенным (провайдер И модель каждого), И
- КАЖДАЯ запись набора проходит ТЕКУЩИЙ allow-list (ужесточили список → старый кэш от
  теперь-запрещённой модели больше не годен — R2-F1).

Иначе классы fail-open: (1) отревьюил дешёвым codex → кэш; позже для рискованного изменения
`both` → кэш попадает → гейт ЗАЯВЛЯЕТ двухглазое ревью, которого не было; (2) кэш от
`cursor`+GPT-модели удовлетворяет запрос `cursor`+Grok → подменяется запрошенное кросс-модельное
РАЗНООБРАЗИЕ (см. ниже про семейства); (3) атрибуция судьи ломается при смене провайдера.
Запись БЕЗ поля `reviewers` (легаси, до фичи) годна только для запроса `codex` — иначе старый
кэш «удовлетворял» бы `both`.

**Про семейства моделей (важно для смысла `both`).** Codex-ревью фактически идёт на
`gpt-5.6-sol` (дефолт `~/.codex/config.toml`, effort high) — это семейство **GPT**. Поэтому
второй ревьюер по умолчанию — **Grok** (`cursor-grok-4.5-high`): именно смена СЕМЕЙСТВА даёт
находки, которые одно семейство систематически не видит. Если `CURSOR_REVIEW_MODEL` укажет
GPT-модель (напр. `gpt-5.3-codex-high-fast`), `both` вырождается в односемейную панель — это
допустимо (два прогона всё же лучше одного, полезно для калибровки серии), но факт виден в
`reviewers` вердикта, и гейт НЕ заявляет разнообразия, которого нет.

**Адаптер cursor — в КОДЕ гейта, не в шаблоне-скрипте.** Причина: три вещи обязаны быть
неотключаемыми — (а) allow-list модели, (б) `--trust` + собственный таймаут, (в) `--mode ask`
(read-only). В user-editable шаблоне их можно снять, и гейт молча станет самопроверкой.

```
cursor-agent -p --output-format json --mode ask --trust --model <PINNED> <промпт>
```
- **Модель пиньуется в коде**: `_CURSOR_MODEL = "cursor-grok-4.5-high"`. Оверрайд возможен
  только через env `CURSOR_REVIEW_MODEL` и **валидируется allow-list'ом не-Anthropic
  значений**; `claude-*`, `auto`, неизвестное → **БЛОК**. Обоснование в эмпирике: Claude пишет
  код в этом контуре, Claude-ревьюер = самопроверка (в списке моделей Cursor есть Opus/Fable);
  `auto` опасен скрытой маршрутизацией.
- **Промпт** = наш текст-контракт (`Verdict: …` + `- [severity] title (file:line)`) + конституция
  `AGENTS.md` (если есть) + блок адъюдикаций серии (`_adjudication_prompt_block`, чтобы
  переговоры работали и у cursor) + дифф `baseline..HEAD`.
- **Вывод**: `.result` из JSON → в СУЩЕСТВУЮЩИЙ `parse_review_output` (текст-фолбэк-контракт,
  логику парсера НЕ трогаем). `.usage` → в аудит (наблюдаемость затрат: in/out токены).
- **Нормализация narration (найдено живым прогоном 25.07 — иначе провайдер нерабочий).**
  `cursor-agent` в `--mode ask` всё равно пользуется инструментами (читает файлы) и склеивает
  свою narration с ответом БЕЗ перевода строки: `…would be a false-claim fail-open.Verdict:
  needs-attention`. Наш строгий `^Verdict:` (MULTILINE) при этом не матчится → вердикт был бы
  «невалиден» всегда. Фикс — **в адаптере, а не в парсере**, по правилу **РОВНО ОДНО вхождение**
  `Verdict:\s*(approve|needs-attention)`: нет вхождений → invalid → fail-closed; БОЛЬШЕ ОДНОГО →
  **ambiguous → invalid → БЛОК** (выбор «последнего» спуфился цитатой `Verdict: approve` ниже
  реальной находки — R2-F2); ровно одно → парсеру передаётся текст с него, и блок обязан пройти
  ПОЛНУЮ валидацию парсера. Парсер и его строгость не трогаем (единый контракт всех провайдеров).
- **Границы**: дифф больше `_CURSOR_DIFF_LIMIT` (≈300k символов) → блок с явным сообщением
  (сузить диапазон / использовать codex), а не молча усечённое ревью.

## Ф2. Сессионное выключение ревьюера

CLI: `review-disable "<причина>"` / `review-enable` / статус в `review-status`.
Маркер — **пер-сессионный** файл `.claude/.review-disabled-<session>` (тот же паттерн, что
design-маркер): истекает сам со сменой сессии, чужую сессию не глушит.

**Что делает выключение (и чего НЕ делает):**

| Слой | Поведение при выключенном ревьюере |
|---|---|
| G1 дизайн-гейт | **пропускает** правки кода (дизайн-гейт fail-open **by design**, BS3: недоступность ревьюера не должна стопорить мышление) + ГРОМКИЙ баннер при каждом пропуске |
| Вызовы ревью | **не выполняются** (не жгут квоту/время) |
| Деплой-гейт `check-reviewed` | **БЛОК ДО любой кэш-ветки** (R2-F3: проверка маркера обязана идти ПЕРЕД `read_valid_ledger`, иначе валидный кэш разрешит деплой ранним возвратом) — с ДВУМЯ реальными выходами: `review-enable` (вернуть ревьюера) ИЛИ аварийный `CODEX_REVIEW_SKIP=1` (аудируется). Смену провайдера как выход НЕ предлагаем (R1-F3): маркер выключает ревью в сессии независимо от провайдера — это был бы ложный совет |
| `check-decision` (перед выкаткой) | **БЛОК** (та же причина) |
| Вердикт для inframon | НЕ пишется (деплой заблокирован — консистентно с V4: блок → нет вердикта) |

**Почему деплой не открывается (ключевое решение).** Сессионный выключатель персистентен и
незаметен — это ровно «забытый kill-switch» из actuator-safety. Открывать им деплой означало бы
превратить один ввод в бессрочный тихий обход money-guard'а. При этом ничего не теряется: для
деплоя уже есть per-command аудируемый `CODEX_REVIEW_SKIP=1`, а деплой редок — префикс раз в
деплой это пренебрежимое трение против невидимого постоянного обхода. Выключатель снимает
именно частую боль (G1 требует ревью, вызовы падают по квоте).

**Требования actuator-safety к самому выключателю:**
- **Громкий, пока включён**: КАЖДЫЙ проход гейта при выключенном ревьюере печатает баннер
  «⚠️ РЕВЬЮЕР ВЫКЛЮЧЕН в этой сессии (причина: …) — G1 пропускает правки; деплой заблокирован».
  Никакого «тихо работает как будто всё нормально».
- **Причина обязательна** (как у адъюдикаций): `review-disable` без причины → ошибка.
- **Аудит** на включение и на выключение (кто/когда/почему).
- **Сам себя не переживает**: пер-сессионность = авто-истечение; кросс-сессионный «навсегда
  выключен» невозможен by construction.

## Ф3. Режим `both` — панель из двух независимых ревьюеров

`REVIEW_PROVIDER=both` — оба провайдера ревьюят ОДИН и тот же дифф в ОДНОМ прогоне гейта.
Смысл: по нашей же эмпирике (arxiv 2604.19049) кросс-модельное разнообразие — главный источник
находок, которые одно семейство систематически не видит (16% пропущенных фиксов). Для
дорогих/необратимых изменений это верный размен: цена — один лишний вызов cursor (~$0.05,
Codex маржинально бесплатен по подписке), выигрыш — второй независимый взгляд.

**Правила агрегации:**
- **Объединение находок (union), блок при blocking у ЛЮБОГО.** Больше глаз → строже; ни один
  провайдер не может «переголосовать» находку другого. Голосования/majority НЕТ осознанно:
  для guard'а важен пропуск (fail-open), а не ложная тревога, поэтому union, а не консенсус.
- **Один прогон = ОДИН раунд серии сходимости** (`rounds += 1`, не 2). Иначе hard-cap выгорает
  вдвое быстрее и carry-over/эскалация срабатывают преждевременно — режим `both` не должен
  наказывать за тщательность.
- **Каждая находка помечается провайдером** (в записи раунда ledger), чтобы при адъюдикации
  было видно, кто её поднял, и чтобы дальнейшие `[DUP:Fx]`-переговоры не путались.
- **Отказ ЛЮБОГО провайдера → БЛОК** (не «сойдёт и один»). Основание — уже действующее в
  системе правило «настроенный источник упал → блок, без тихого фолбэка»: так себя ведут
  `deploy.baseline_command` (EARS-2 inframon-спеки) и `empirical.test_command`. Оператор просил
  двухглазое ревью для рискованного изменения; получить одноглазое и не заметить — это тихая
  подмена заявленной проверки. Осознанное понижение доступно одним явным шагом:
  `REVIEW_PROVIDER=codex` (или `cursor`).
- Оба провайдера получают ОДИНАКОВЫЙ промпт (включая блок адъюдикаций серии) — иначе
  расхождение вердиктов нельзя интерпретировать.

**Механика прохода (как именно выполняется доп-проход cursor):**
1. **Последовательно, codex → cursor, в ОДНОМ вызове гейта.** Wall-clock = сумма (~2–5 мин
   Codex + ~1–2 мин cursor). Выбрано ради читаемого вывода и однозначной атрибуции отказа;
   параллельный запуск — принятая возможная оптимизация позже (риск низкий, выигрыш — max
   вместо суммы), но не в v1: гейт для «сложных случаев» запускается редко.
2. **Промпт cursor собирается гейтом**, не берётся из репо: наш текст-контракт + `AGENTS.md`
   (конституция проекта) + блок адъюдикаций серии + сам дифф `baseline..HEAD` (лимит
   `_CURSOR_DIFF_LIMIT`). Дифф передаётся ЯВНО, поэтому ревью не зависит от того, что cursor
   решит прочитать сам.
3. **cursor может дополнительно читать worktree** (в живом прогоне 25.07 он так и сделал —
   «cross-check a few gate invariants in the repo»). Это допустимо и полезно: режим `--mode ask`
   read-only, правок он внести не может (bounded authority), а дополнительный контекст улучшает
   находки. Недетерминизм здесь безопасен: обязательная часть входа — переданный дифф.
4. **Второй проход выполняется ДАЖЕ ЕСЛИ первый нашёл blocking.** Никакого short-circuit: цель
   `both` — собрать ПОЛНЫЙ union находок за ОДИН раунд, чтобы адъюдицировать всё сразу.
   Short-circuit прятал бы находки cursor до следующего раунда и ломал сходимость (они выглядели
   бы «новыми»). Цена — один вызов ~$0.05.
5. **Если ЛЮБОЙ провайдер отказал** (invalid/outage/таймаут/quota) — **блок**, и раунд считается
   НЕсостоявшимся: `rounds` НЕ инкрементится (инвариант проверен живьём на quota-деградации
   Codex 25.07: «раунды не сгорают на outage» — иначе недоступность провайдера выжигала бы
   hard-cap). **НО находки успешного провайдера ВЛИВАЮТСЯ в ledger** (R4-F1, найдено ревью —
   иначе достижимая потеря): если Codex вернул high, а cursor упал, находка обязана остаться в
   памяти серии, иначе на следующем прогоне (тем более после осознанного понижения до одного
   провайдера) недетерминированный ревьюер может её не повторить — и реальный дефект молча
   исчезнет. Разделяем два требования: **память серии — да, инкремент раунда — нет**. Такие
   находки помечаются `from_partial_round: true` + провайдером; флаг `needs_review_round` при
   частичном раунде НЕ сбрасывается (адъюдикации не были показаны ВСЕМ запрошенным ревьюерам —
   fail-closed).
6. **Кэш чистого ревью пишется только если union чист И оба провайдера успешны**, с
   `reviewers` из обоих (иначе см. ML-R10/ML-R12).

| P19 | `both`, первый (codex) нашёл blocking | второй проход ВСЁ РАВНО выполняется; union за один раунд (нет short-circuit) |
| P20 | `both`, один отказал | блок И `rounds` НЕ инкрементится (инвариант quota-теста) |
| P20b | `both`, codex вернул blocking, затем cursor отказал | блок; находка codex ВЛИТА в ledger (`from_partial_round`), `rounds` не инкрементится, `needs_review_round` не сброшен (R4-F1) |
| P20c | `both`, оба отказали (ничего не найдено) | блок; ledger не меняется (нечего вливать) |
| P21 | `both`, union чист, оба успешны | кэш записан с `reviewers` из обоих |
| M1 | D5 `claude-*` через env | **БЛОК** — allow-list в коде (независимость) |
| M2 | D5 `auto` | **БЛОК** (скрытая маршрутизация) |
| M3 | D5 мусор/неизвестная модель | **БЛОК** (не «пусть cursor решит») |
| M4 | D5 валидный не-Anthropic оверрайд (напр. `gpt-5.3-codex-high-fast`) | принят, в аудит |
| S1 | `review-disable "причина"` | маркер сессии, аудит, подтверждение |
| S2 | `review-disable` без причины | ошибка, маркер НЕ пишется |
| S3 | выключен + G1 правка кода | **пропуск** + ГРОМКИЙ баннер (fail-open by design) |
| S4 | выключен + `check-reviewed` | **БЛОК** + ровно ДВА выхода (`review-enable` / `CODEX_REVIEW_SKIP=1`) |
| S12 | выключен + ВАЛИДНЫЙ кэш чистого ревью того же набора | **БЛОК** — маркер проверяется ДО кэш-ветки (R2-F3) |
| S5 | выключен + `check-decision` | **БЛОК** |
| S6 | выключен → вызовы ревью | НЕ выполняются (квота не жжётся) |
| S7 | `review-enable` | маркер снят, аудит; гейты снова штатны |
| S8 | новая сессия (другой session id) | маркер прошлой НЕ действует (авто-истечение) |
| S9 | выключен + `CODEX_REVIEW_SKIP=1` на деплое | allow (аварийный контур жив) + оба факта в аудите/вердикте |
| S10 | выключен, D6 сессия неизвестна | `review-disable` → ошибка (нечего скоупить, fail-closed); гейты — как обычно |
| S11 | выключен + вердикт | НЕ пишется (деплой блокирован) |

Полнота: каждое значение D1–D9 встречается; ключевые комбинации — выключен×слой (S3/S4/S5),
провайдер×отказ (P3–P6), both×комбинации исходов (P9–P13, P9b), кэш×набор провайдеров
(P14–P16), narration (N1–N4), модель-независимость (M1–M3), авто-истечение (S8), аварийный
контур поверх выключателя (S9).

Осознанно ВНЕ scope: панель из 3+ провайдеров и режимы состава (`reviewers.yaml` — идея Фазы 2
источника); авто-фоллбэк по quota-ошибке (отвергнут, см. ниже); кросс-сессионное выключение
(противоречит «сам себя не переживает»); кросс-провайдерный семантический дедуп находок
(ML-R9).

## EARS

- **EARS-1:** WHERE `REVIEW_PROVIDER` не задан — SHALL использоваться `codex` (поведение как до
  фичи). (P1)
- **EARS-2:** WHEN `REVIEW_PROVIDER=cursor` — ревью SHALL выполняться `cursor-agent` с
  `-p --output-format json --mode ask --trust`, пиньованной моделью и собственным таймаутом;
  `.result` SHALL парситься существующим `parse_review_output`. (P2)
- **EARS-3:** IF значение `REVIEW_PROVIDER` не из {`codex`, `cursor`, `both`} — THEN гейт SHALL
  заблокировать (fail-closed), НЕ откатываясь на codex. (P7)
- **EARS-4:** IF модель ревьюера (дефолт или env-оверрайд) не входит в allow-list
  не-Anthropic — THEN гейт SHALL заблокировать; `claude-*` и `auto` SHALL быть запрещены
  всегда. (M1–M3)
- **EARS-5:** Провайдер(ы) (и модель для cursor) SHALL записываться в аудит, в раунд
  finding-ledger и в вердикт — поле `providers` ВСЕГДА список (схема 2). (P2, P9)
- **EARS-5b:** `read_valid_ledger` SHALL признавать кэш годным ТОЛЬКО если (а) набор
  `reviewers: [{provider, model}]` записи ТОЧНО совпадает с запрошенным (провайдер И модель
  каждого) И (б) КАЖДАЯ его запись проходит ТЕКУЩИЙ allow-list моделей; запись без поля
  `reviewers` (легаси) — только для запроса `codex`. Сравнение только по провайдерам ЗАПРЕЩЕНО
  (кэш `cursor`+GPT удовлетворял бы запрос `cursor`+Grok — R2-F1). (P14–P18)
- **EARS-6:** IF cursor-адаптер вернул нарушение формата / auth-ошибку / таймаут / quota /
  дифф сверх лимита — THEN деплой-гейт SHALL заблокировать и напечатать причину. (P3–P6, P8)
- **EARS-12:** WHEN `REVIEW_PROVIDER=both` — оба провайдера SHALL ревьюить один дифф в одном
  прогоне; находки SHALL объединяться (union); деплой SHALL блокироваться при blocking у
  ЛЮБОГО. (P9–P11)
- **EARS-13:** В режиме `both` счётчик раундов серии SHALL увеличиваться на 1 за прогон
  (не на число провайдеров). (P9)
- **EARS-14:** IF в режиме `both` ЛЮБОЙ провайдер не выдал валидный вердикт — THEN гейт SHALL
  заблокировать (без деградации до одного ревьюера), назвав отказавшего и причину, И SHALL НЕ
  инкрементировать `rounds` (раунд не состоялся). (P12, P13, P20)
- **EARS-14c [R4-F1]:** При частичном раунде находки УСПЕШНОГО провайдера SHALL вливаться в
  finding-ledger (помеченные `from_partial_round: true` и провайдером), чтобы уже обнаруженный
  blocking не потерялся между прогонами; `needs_review_round` SHALL НЕ сбрасываться. (P20b, P20c)
- **EARS-14b:** В режиме `both` второй проход SHALL выполняться даже при blocking-находках
  первого (union за один раунд, без short-circuit). (P19)
- **EARS-15:** Каждая находка SHALL нести пометку провайдера, её поднявшего. (P11)
- **EARS-7:** WHEN `review-disable "<причина>"` — SHALL писаться пер-сессионный маркер и
  аудит; IF причина пуста — THEN команда SHALL завершиться ошибкой без записи. (S1, S2)
- **EARS-8:** WHILE ревьюер выключен в сессии — G1 SHALL пропускать правки кода с ГРОМКИМ
  баннером; вызовы ревью SHALL НЕ выполняться. (S3, S6)
- **EARS-9b [R2-F3]:** Проверка маркера выключения SHALL выполняться ДО `read_valid_ledger` и
  до любого раннего allow по кэшу; единственное исключение — осознанная ветка
  `CODEX_REVIEW_SKIP=1`. (S12)
- **EARS-9:** WHILE ревьюер выключен — `check-reviewed` и `check-decision` SHALL блокировать,
  предлагая ровно ДВА действующих выхода: `review-enable` ИЛИ аудируемый `CODEX_REVIEW_SKIP=1`
  (смена провайдера выключение НЕ обходит — не предлагать). (S4, S5)
- **EARS-10:** Маркер выключения SHALL быть пер-сессионным (не действует в другой сессии). (S8)
- **EARS-11:** `CODEX_REVIEW_SKIP=1` SHALL продолжать работать при выключенном ревьюере
  (аварийный контур), с фиксацией обоих фактов. (S9)

## BSAC

Бизнес-сценарии:
- **BS-R1:** при исчерпанной квоте одного провайдера работа продолжается через другого —
  явным переключением, со следом кто судил. (P2, EARS-5)
- **BS-R2:** в сессии с недоступным ревьюером не блокируется мышление и не жжётся квота, но
  деплой не проезжает. (S3, S4, S6)
- **BS-R3:** независимость ревью не может быть снята конфигом/env — только не-Anthropic
  модели. (M1–M3)
- **BS-R4:** для дорогого/необратимого изменения можно потребовать ДВА независимых ревью, и
  «получилось одно» не пройдёт незамеченным. (P9–P13)

Денежные / fail-open краевые случаи:
- **ML-R1 [главный]** сессионное выключение открывает деплой → бессрочный тихий обход
  money-guard. → **Закрыто решением:** выключение НЕ открывает деплой (S4/S5); для деплоя
  остаётся per-command аудируемый скип; выключатель громкий и пер-сессионный.
- **ML-R2** опечатка в `REVIEW_PROVIDER` → тихо ревьюит codex, оператор думает, что cursor
  (или наоборот) → неверная модель доверия. → P7 блок.
- **ML-R3** `REVIEW_PROVIDER=cursor` + `CURSOR_REVIEW_MODEL=claude-opus-5-…` → гейт становится
  самопроверкой, продолжая рапортовать «независимое ревью». → M1 блок (allow-list в коде).
- **ML-R4** cursor вернул «почти формат» (напр. без `Verdict:`) → парсер invalid → блок
  (существующая механика, регресс).
- **ML-R5** смена провайдера посреди серии сходимости → адъюдикации/`[DUP:]` теряют
  преемственность (разные калибровки severity). → провайдер пишется в раунд; в промпт cursor
  передаётся блок адъюдикаций; **остаток:** кросс-провайдерная калибровка severity —
  осознанно не решаем (эскалация к человеку при споре уже есть).
- **ML-R6** cursor-агент имеет доступ к файлам и мог бы что-то изменить → `--mode ask`
  (read-only) + отсутствие `--force/--yolo` в коде адаптера (bounded authority).
- **ML-R10 [R1-F1, найдено ревью]** кэш чистого ревью не привязан к провайдеру → запрос `both`
  удовлетворяется записью от одного → гейт ЗАЯВЛЯЕТ двухглазое ревью, которого не было. →
  EARS-5b: кэш годен только при совпадении набора; легаси-запись — только для `codex`.
- **ML-R12 [R2-F1]** кэш привязан к провайдеру, но не к модели → подмена запрошенного
  разнообразия старым односемейным прогоном; ужесточение allow-list не инвалидирует кэш. →
  `reviewers: [{provider, model}]` + переоценка по текущему allow-list (P17, P18).
- **ML-R13 [R2-F3]** ранний allow по валидному кэшу срабатывает раньше проверки маркера
  выключения → «выключенный» ревьюер всё равно пускает деплой. → EARS-9b: маркер ДО кэша (S12).
- **ML-R11 [найдено живым прогоном; уточнено R2-F2]** narration cursor склеивается с вердиктом → всегда invalid
  → провайдер нерабочий (или, при наивном ослаблении парсера, narration могла бы выдать себя за
  вердикт). → нормализация в адаптере + полная валидация извлечённого блока (N1–N4).
- **ML-R14 [R4-F1]** отказ второго провайдера стирал уже найденный blocking первого → на
  следующем прогоне недетерминированный ревьюер может его не повторить → реальный дефект молча
  исчезает (ledger — единственная память серии). → EARS-14c: находки вливаются, раунд не
  инкрементится.
- **ML-R8** режим `both` тихо деградировал до одного (второй умер по квоте) → оператор думает,
  что рискованное изменение прошло двухглазое ревью. → EARS-14 блок (то же правило, что у
  `baseline_command`/`test_command`: настроенный источник упал = блок).
- **ML-R9 [остаток]** одна и та же проблема поднята обоими провайдерами → две записи в ledger →
  адъюдицировать надо дважды. Осознанно: трение, не дыра (авто-семантик-дедуп хрупок — тот же
  вывод, что в протоколе сходимости). Фикс обеих одной причиной допустим.
- **ML-R7 [остаток]** выключатель забыт в долгой сессии → громкий баннер на каждом проходе +
  деплой всё равно блокирован; кросс-сессионно не переживает.

## Actuator-safety (Tier 2)

- **Монитор исхода:** провайдер и факт выключения видны в аудите, ledger и вердикте (inframon
  может ими рулить); баннер — при каждом проходе.
- **Kill-switch:** `review-disable` — сам является kill-switch'ом ревьюера, поэтому обязан быть
  громким и авто-истекающим; аварийный контур деплоя (`CODEX_REVIEW_SKIP`) сохранён отдельно.
- **Ограниченные полномочия:** модель — allow-list в коде; cursor — read-only режим; таймаут;
  лимит размера диффа.
- **Recovery:** `review-enable` (и просто новая сессия).

Определение готово: реальный маршрут воспроизведён — (1) ревью через cursor РЕАЛЬНО проходит
и его вердикт влит в серию с пометкой провайдера; (2) при выключенном ревьюере G1 пропускает
правку, а `check-reviewed` блокирует.

## Отвергнутые альтернативы

- **Авто-фоллбэк codex→cursor при quota-ошибке.** Отвергнут: смена судьи посреди серии без
  явного решения оператора; вердикт «кто ревьюил» становится недетерминированным. Явное
  переключение дешевле и честнее.
- **Провайдер в `.codex-gate.yaml`.** Отвергнут: операционное решение момента, а в конфиге
  потребовало бы pin-механику (как `deploy`-секция) без выигрыша.
- **Адаптер как шаблон-скрипт в репо проекта.** Отвергнут: снимаемые `--trust`/`--mode ask`/
  модель = снимаемая независимость. Адаптер живёт в коде плагина.
- **Сессионное выключение, открывающее деплой.** Отвергнуто (ML-R1): бессрочный невидимый
  обход money-guard'а; per-command аудируемый скип уже покрывает потребность.
- **Усечение большого диффа для cursor.** Отвергнуто: усечённое ревью выглядит как полное —
  лучше блок с инструкцией (P8).
- **В режиме `both` громко деградировать до одного при отказе второго.** Отвергнуто (ML-R8):
  противоречит уже действующему в системе правилу «настроенный источник упал → блок»
  (`baseline_command`, `test_command`); заявленный уровень проверки не должен молча падать.
  Осознанное понижение — один явный env-шаг.
- **Голосование/majority в режиме `both`.** Отвергнуто: для guard'а опасен ПРОПУСК, а не ложная
  тревога; majority позволил бы одному провайдеру «отменить» находку другого. Union строже и
  проще для интерпретации.
- **`both` как дефолт.** Отвергнуто: удваивает стоимость и время на каждом деплое; режим для
  сложных случаев включается осознанно.

## Тестирование

Юнит (стабы `cursor-agent` через env-подмену команды адаптера, как `CODEX_COMPANION_CMD`):
P1–P21 (вкл. P20b/P20c), N1–N4, M1–M4, S1–S12 из матрицы. Явно: частичный раунд — находка
успешного провайдера ЕСТЬ в ledger, `rounds` не изменился, `needs_review_round` не сброшен. Явно: ambiguous-Verdict спуф (N2 — реальный blocking
выше, цитата `Verdict: approve` ниже → БЛОК, не approve); выключен + валидный кэш → блок (S12);
кэш от другой модели/после ужесточения allow-list не годен (P17, P18). Для `both`: оба-чисто (rounds +1 — проверить ИМЕННО счётчик),
один-блокирует, оба-блокируют (обе находки с провайдерами), один-отказал → блок, оба-отказали. Явно: allow-list модели (M1/M2 — блок, не warning);
неизвестный провайдер (P7); выключен×слой (S3 пропуск с баннером / S4-S5 блок); авто-истечение
по сессии (S8); `CODEX_REVIEW_SKIP` поверх выключателя (S9); провайдер в раунде ledger и в
вердикте (P2, схема 2). Регресс: все существующие codex-тесты зелёные при `REVIEW_PROVIDER`
не заданном (P1). Живой смоук: одно реальное ревью через cursor (эмпирика 25.07: на простом диффе формат чистый,
на длинном — с narration → нормализация обязательна) + проверка, что `usage` попал в аудит.
Регресс кэша: запись от `codex` НЕ удовлетворяет запрос `both`/`cursor` (P14–P16).
