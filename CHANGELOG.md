# Changelog

## 0.9.1 — 2026-08-13

Хотфикс: **лесенка была неисполнима в четырёх формах репозитория**, и её отказ выглядел как
непройденное ревью. Обновляться обязательно всем, у кого в репо есть симлинки, подмодули или
sparse checkout. Дизайн и воспроизведения: `docs/2026-08-13-symlink-tree-hash-fix-design.md`.

### `compute_tree` строится от индекса, а не угадывает вид записи по `is_file()`

Один корень у всех четырёх дефектов: функция считала, что запись дерева — это регулярный файл,
хэшируемый по пути. Инвариант теперь сформулирован явно — `compute_tree` == дерево, которое дал
бы `git add -A && git write-tree`, — и проверяется тестами на РАВЕНСТВО настоящему дереву git'а,
а не на «не упало».

- **Симлинки (инцидент 0.9.0, critical).** `hash-object` по пути разыменовывает ссылку: на
  цели-директории git отвечает `fatal: Unable to add (null) to database` — лесенка падала на
  `begin`/`mark`, и единственным путём коммита оставался `LADDER_SKIP=1`. Вторая, тихая половина:
  симлинк на **файл** не падал, а молча получал блоб СОДЕРЖИМОГО цели при режиме `120000`, то
  есть tree-хэш врал, и маркер «отревьюено» привязывался к дереву, которого не существует.
  Теперь блоб — текст цели сырыми байтами (цель может быть не-UTF-8; текстовый режим ронял
  `UnicodeEncodeError` мимо всей диагностики).
- **Подмодули (critical, найдено дизайн-ревью).** gitlink выпадал из дерева, а в `index_tree`
  он есть всегда — значит **честная полная цепочка не могла дать `check_precommit == 0`
  никогда**. Репозиторий с подмодулем был так же неисполним, как с симлинком на директорию.
  Теперь mode 160000 берётся из HEAD инициализированного подмодуля (сдвиг указателя виден и
  ломает цепочку), из индекса — для неинициализированного, и выпадает при удалении каталога.
- **Sparse checkout (найдено дизайн-ревью).** `SKIP_WORKTREE`-запись отсутствует на диске, но
  остаётся в индексе; трактовка «нет файла = удалён» разводила `compute_tree` и `index_tree` в
  ЛЮБОМ sparse-checkout репозитории — на обычных файлах, не только на подмодулях. Различается
  по флагу `ls-files -v`; комбинированный флаг `s` (skip-worktree + assume-unchanged) считается
  skip-worktree. `assume-unchanged` по-прежнему НЕ прячет правку от tree-хэша.
- **Конфликтный merge.** Пути со stage != 0 схлопываются в одну stage-0 запись с содержимым с
  диска — как поступил бы `git add -A`.

### Отказ движка больше не маскируется под «ревью не пройдено»

Сломанный `compute_tree` печатал штатное «цепочка … не подтверждена» с подсказкой `LADDER_SKIP`
в конце: оператор читал отказ инфраструктуры как собственную забывчивость, и подсказка вела
прямо к обходу гейта. Так поломка прожила двое суток незамеченной.

- Отдельный громкий баннер **«⛔ ДВИЖОК ГЕЙТА СЛОМАН — лесенка НЕИСПОЛНИМА»** с причиной,
  трейсбеком и явной пометкой, что `LADDER_SKIP` здесь — обход ОТКАЗА ДВИЖКА, а не забытого
  прохода. `check_precommit` перед тем, как звать «пройди лесенку», проверяет, что её физически
  можно пройти.
- Ловится **любое** исключение, а не перечень типов: форм отказа нашлось четыре за один день.
  Это не проглатывание — баннер печатается ВМЕСТЕ с полным трейсбеком, код возврата ненулевой,
  ни одна ветка не начинает пропускать коммит. `begin`/`mark` дают код 3 вместо трейсбека;
  `check_precommit` как блокировал (2), так и блокирует.
- Тексты ошибок несут код возврата и stderr git'а (`redact_secrets`): без них
  `не посчитать хэш X` не диагностировался и причину пришлось воспроизводить руками.

### Закрыт канал подмены: невидимое содержимое

Найдено ревью уже по коду фикса (три раунда код-ревью + security-ревью), каждая форма
воспроизведена. Класс один: **запись, взятая из ИНДЕКСА, а не пере-хэшированная с диска, —
это содержимое, которого ревьюер физически не видит, а индекс наполняет проверяемая сторона.**
Формы: `skip-worktree` с файлом на диске, `skip-worktree` без файла, деинициализированный
подмодуль, и — самая тяжёлая — подмена самого базиса сравнения.

Правило теперь одно и живёт в одной функции: **невидимое проходит ревью, только если оно не
менялось с последнего коммита.** Совпало с HEAD — ревьюить нечего, законный sparse checkout и
законный `submodule deinit` работают. Разошлось — отказ, с требованием вернуть содержимое в
рабочее дерево.

Отдельно: базис нельзя было брать на веру. `HEAD` — обычная ссылка, её переставляют
`git symbolic-ref` на чужую ветку, НЕ трогая ни индекс, ни рабочее дерево; там спрятанное
содержимое «не менялось», лесенка проходится целиком, HEAD возвращается — и в коммит уезжает
бэкдор с честными маркерами, полным ledger'ом и покрытым диапазоном у деплой-гейта
(воспроизведено end-to-end). Поэтому исключение перепроверяется на pre-commit против того
HEAD, на который коммит реально ложится.

### Отказ доверия ≠ поломка движка

`GateRefusal` (подмена git, невидимое расхождение) печатается своим баннером и **без рецепта
`LADDER_SKIP`**: обход — ровно то, чего добивается подмена. Рецепт остаётся только для
настоящей поломки движка, где оператор иначе заперт.

### Совместимость

Формат маркеров, ledger'а и протокол `begin`/`mark` не менялись. **Но tree-хэши репозиториев с
симлинками, подмодулями или sparse checkout теперь другие** (прежние были неверны): маркеры,
снятые 0.9.0 в таких репо, не совпадут — цепочку надо пройти заново. В репозиториях без таких
записей хэши прежние, и существующие маркеры остаются валидны.

## 0.9.0 — 2026-08-11

Крупный релиз: стерильный git-слой, арбитр-третья-модель (пока неактивен) и бюджет раундов
ревью. **Есть ломающие изменения — см. «Миграция».**

### Стерильный git-слой

Гейт судил о коде по данным git, а все вызовы шли голым `git` в окружении вызывающего — то
есть той стороны, чей код проверяют. Закрыты три класса, каждый — «решение принимается по
представлению, которым управляет проверяемая сторона»:

- **вход ревьюеров строится из дерева, а не из `git diff`.** Строка `*.py -diff` в
  `.gitattributes` возвращала «Binary files differ» вместо кода, и оба обязательных ревьюера
  одобряли непрочитанный payload. Формат — канонический tree-delta с конвертом из OID
  деревьев, gitlink'ами, типом симлинка и sha256 бинарей. **Сдвиг подмодуля на чужой коммит
  был полностью невидим** — воспроизведено;
- **состояние, влияющее на решение, вынесено из репозитория** в
  `~/.local/state/claude-gates/<ключ>`. Ветка с маркером baseline = HEAD делала диапазон
  пустым: ревьюеры честно одобряли пустоту, и это «одобрение» навсегда исключало
  предшествующий код из ревью;
- **`deploy.baseline_command` — закрытая форма:** один абсолютный исполняемый файл вне
  репозитория, без аргументов, `cwd=/`, `stdin=DEVNULL`.

Прочее: probe падает закрыто на исполняемых при checkout фильтрах, хуках `post-checkout` и
promisor'ах; `remote.uploadpack` больше не исполняется при pre-push fetch; артефакт байтоверен
и падает на подмодулях; бинарные изменения блокируют деплой.

### Арбитр-третья-модель — реализован, НЕ активен

Терминален ровно один класс (`duplicate` с сохраняемым инвариантом графа под series-lock);
всё остальное — предложение, которое принимает человек. Запись Fable в реестре — `candidate`,
роль требует `verified`, поэтому **арбитр не вызывается и гейт ведёт себя как до фичи**.

Категория находки и пересертификация панели закрыты как остаток `R-CATEGORY-CONTRACT`:
разбор сохранён в `docs/2026-08-10-reviewer-category-contract-design.md`, реализации нет.

### Бюджет раундов ревью (стоп-политика v3)

Ярус объявляется в `.codex-gate.yaml` до цикла: `money`=5, `decision`=3, `convenience`=1;
неизвестное или отсутствующее → `money`. Гейт печатает `раунд N из M` и по исчерпании
отказывается стартовать следующий. Остатки принимает человек, реестр находок при этом не
трогается — открытые блокирующие продолжают блокировать деплой.

Промпт ревьюера требует по каждой находке самую дешёвую правку отдельно от полной.

### Починка

`companion-review` вис бесконечно при заявленном потолке 900 с: `subprocess.run(timeout=)`
убивает только прямого потомка, а внуки node держат stdout. Замерено зависание на 46 минут.

## Миграция с 0.8.0

Порядок важен: рецепт 0.8.0 вызывает `check-decision` без `--head`, который 0.9.0 отклоняет
ДО выкатки, и не содержит `finalize-deploy`, записывающего новый baseline. Поэтому сначала
рецепт, и только потом первый деплой.

1. **Обнови Makefile из шаблона плагина** (`plugins/gates/templates/Makefile.snippet`):
   `check-decision` теперь требует `--head`, перед выкаткой добавился `check-artifact`, после
   неё — `finalize-deploy`.
2. **Переопредели `deploy-payload` и `verify-deployed`** — скелет намеренно падает, пока они
   не заменены: иначе цель рапортовала бы успех и двигала baseline на код, который никуда не
   уехал. Проверь оба на реальном хосте.
3. **Задай baseline один раз.** Он переехал из репозитория и больше не читается из
   `.claude/.last-deployed-sha`, поэтому первый деплой остановится fail-closed. Разово:
   `CODEX_DEPLOY_BASELINE=<sha фактически развёрнутой версии> make deploy`. Дальше гейт ведёт
   маркер сам — и двигает его только при evidence от КАЖДОГО обязательного ревьюера.
4. **Бинарные изменения блокируют деплой.** Их содержимое не видит ни один ревьюер, а в
   артефакт они уезжают целиком. Осознанный обход: `GATES_ALLOW_BINARY=1` (аудируется,
   baseline при этом НЕ двигается — диапазон остаётся в области следующего ревью).
5. **Проекты с Git LFS.** Обычный LFS настраивает `smudge`+`process`, а `worktree add`
   исполнил бы их правами гейта, поэтому интеграционный probe отказывает. Рабочий компромисс —
   пропустить ТОЛЬКО probe, сохранив проверку конфликтов слияния:

   ```bash
   INTEGRATION_TESTS_SKIP=1 \
     INTEGRATION_TESTS_SKIP_REASON='Git LFS: probe несовместим (R-PROBE-SMUDGE)' \
     git push
   ```

   Что теряется: тесты на смерженном дереве. Что остаётся: предсказание конфликтов. Постоянный
   вариант — убрать `integration.merge_test_command` из `.codex-gate.yaml`; такая правка секции
   требует `INTEGRATION_CONFIG_CHANGE=1` с причиной на переходном push (анти-самоослабление).
6. **Дизайн-ревью**: добавь `--design-file <путь>` в вызов `companion-review`, иначе дизайн
   попадёт под кодовый бюджет раундов.
7. **Ярус ревью**: добавь в `.codex-gate.yaml` секцию `review: {tier: money|decision|convenience}`.
   Без неё действует `money` (5 раундов).

## 0.8.0 — 2026-08-07

- **Обязательная blocking-панель Codex+Claude вместо обязательного Gemini.** 0.7.0 в дефолте
  не пропускал НИКОГО: единственный разрешённый blocking-ревьюер (Gemini) остался `candidate`
  и требовал стороннего ключа, а Codex отсекался хардкодом консервативного author set.
  Теперь панель — пара `codex`(openai) + `claude`(anthropic), оба blocking, фолбэка нет.
  Независимость держится не на доказательстве авторства (хост сессии его не доказывает), а на
  том, что обе возможные авторские семьи всегда в панели, а union не даёт снять чужую находку.
  Роль `supplemental` упразднена.
- **BREAKING: `REVIEW_PROVIDER=codex|cursor|both` больше не работает на деплой-пути.** Эти
  значения означали панель МЕНЬШЕ обязательной, то есть env-обход независимости. Профили могут
  только ДОБАВИТЬ сертифицированного ревьюера. Аварийный выход — прежний `CODEX_REVIEW_SKIP=1`.
- **BREAKING: реестр сертификаций — схема 2** (`portable-review-v2`). Появились `attestation`
  (`declared|verified`) и блок `report`, механически связывающий запись с коммитнутым отчётом
  корпусного прогона. Правка `status` руками больше не изготавливает сертификацию.
- **Сертификация прогнана живьём:** Codex и Claude прошли 20/20 (10 кейсов × 2 повтора) через
  боевые адаптеры; отчёты в `reviewer_corpus/reports/`. `certify_reviewers.py` принимает
  `gemini|codex|claude` и умеет `--write-report`.
- **Закрыты fail-open в протоколе сходимости:** `high` после hard-cap уходил в `carried`;
  аварийный skip терял `critical` при архивации серии; `[DISPUTE]`/`[DUP]` против
  `resolved-by-user` проглатывался, в т.ч. через цепочку дубликатов; `refuted` закрывал чужую
  блокирующую находку молчанием ревьюера.
- Осознанные остатки (`AGENTS.md`): **M8** — Codex не аттестует фактическую модель (`declared`);
  **R-CERT-PROVENANCE** — подписанная провенанс отчётов сертификации, Фаза 2.

## 0.6.0 — 2026-07-26

- **Pre-push интеграционный гейт** (`prepush_gate.py` + шим `.githooks/pre-push`). Обещание
  ровно одно: **слияние с базой не конфликтует**. Конфликты предсказываются `merge-tree` без
  касания рабочего дерева; тесты на смерженной пробе (отдельный worktree, git-хуки отключены)
  запускаются, красные блокируют, а **зелёные не доказывают ничего** — при editable install
  импорт разрешается в настоящее дерево, и пометка об этом печатается ВСЕГДА. Спека:
  `docs/2026-07-26-prepush-integration-gate-design.md` (5 редакций, цикл закрыт на хард-капе).
- **Анти-самоослабление** секции `integration`: референс — предыдущий принятый tip ПУШИМОГО
  ref'а (`<remote sha>`), а не база (она не двигается до мержа). Нечитаемый предыдущий tip,
  пересоздание ветки и пуш по неразрешимому URL блокируются, а не читаются как «новая ветка».
- **Обходы раздельные и аудируемые**: `INTEGRATION_SKIP` (весь гейт), `INTEGRATION_TESTS_SKIP`
  (только тесты — конфликты всё равно проверяются), `INTEGRATION_CONFIG_CHANGE` (смена секции),
  `on_fetch_failure: skip-audited`. Запись в аудит делает сам `_ack`, поэтому будущий вызывающий
  не может её забыть.
- **Security-проход нашёл и закрыл два RCE-класса** (эксплойты воспроизведены): `base_ref` из
  пушимого коммита уходил позиционным argv в `git fetch`, и значение `--upload-pack=<cmd>`
  исполнялось; `merge_test_command` бралась из пушимого коммита, то есть чужая ветка исполняла
  свою команду на машине пушащего при рядовом `git push`. Теперь ref-компоненты валидируются
  (без ведущего дефиса), везде `--end-of-options`, а исполняемая команда читается ТОЛЬКО из
  конфига оператора; политика по-прежнему из коммита (анти-лаундеринг).
- `gates-run` различает «плагин не установлен» и «версия старше шима»: рассинхрон версий
  заблокировал все пуши в репо-носителе, а сообщение диагностировало не ту причину.
- Прочее из ревью: полный путь ветки вместо последнего сегмента (`release/main` считался базой
  и пропускал проверку), `HEAD:refs/heads/x` больше не даёт вечный ложный блок, база по
  умолчанию берётся из `origin/HEAD`, сбой `rev-list` — «неизвестно» → блок.
- Тесты: 384 → 449 (65 по этому гейту), мутационные проверки на каждом круге.
